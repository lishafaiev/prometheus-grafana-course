# Заняття 7 — High Availability для метрик

Дата: 07 липня, 19:00

## Конспект

Один Prometheus — одна точка відмови й обмежений обсяг даних. Підходи до
відмовостійкості та масштабування, розглянуті на занятті:

- **Federation** — ієрархічний збір: центральний Prometheus скрейпить
  агреговані метрики дочірніх через ендпоінт `/federate`.
- **Thanos** — sidecar поруч із Prometheus вивантажує блоки TSDB в обʼєктне
  сховище (довгострокове зберігання), Querier дає єдину точку запитів по всіх
  інстансах. У kube-prometheus-stack вмикається через
  `prometheus.prometheusSpec.thanos.create=true`.
- **Cortex / Mimir** — централізована TSDB, що приймає `remote_write` від
  багатьох Prometheus; масштабується горизонтально.
- **VictoriaMetrics** — альтернативна TSDB, сумісна з PromQL, економніша за
  ресурсами; часто використовується як remote-сховище замість Prometheus.
